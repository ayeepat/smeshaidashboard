# СМЭШ AI — панель аналитики

Внутренняя админ-панель для СМЭШ AI (расширение-помощник по МЭШ). Статический
сайт без сборки: `index.html` + `styles.css` + `app.js`, размещён на GitHub Pages.

**Живой адрес:** https://ayeepat.github.io/smeshaidashboard/

## Что показывает

- **Обзор** — выручка, расход на ИИ (кредиты API), «чистыми», средний чек, DAU/WAU/MAU,
  всего устройств, решения/тесты/ГДЗ, расход на пользователя за день/неделю/месяц;
  графики выручки vs расхода, активных устройств, использования функций,
  разбивка по браузерам и лицензиям.
- **Пользователи** — каждое устройство с расширением. По умолчанию отсортировано
  по **расходу на мои API-кредиты**. Фильтры: браузер (Chrome / Yandex / …),
  лицензия, поиск, сортировка, пагинация. Клик по строке — карточка устройства
  с историей, предметами и событиями.
- **Деньги** — покупки, валовая и чистая выручка (за вычетом возвратов), средний
  чек, шлюзы, реферальная программа. Плюс три блока, отвечающих на вопросы,
  которых оконная выручка не знает:
  - **Подписки сейчас** — MRR, активные подписки, что истекает за 7/30 дней,
    кто не продлил. Это срез на текущий момент, а не за период. MRR нормализует
    каждый план на 30 дней от его собственного срока, поэтому 90-дневная
    покупка не выглядит как всплеск в месяц оплаты. Ключи «навсегда» в MRR
    не входят.
  - **Оформление заказа** — сколько заказов создано, сколько оплачено, сколько
    брошено. Выручка показывает только тех, кто дошёл; здесь видно тех, кто
    ушёл на шаге Robokassa. Заказы, срок которых ещё не истёк, считаются
    активными, а не потерянными.
  - **Сколько стоит обслуживать платников** — что человек заплатил против того,
    во что обошлись его вызовы ИИ. Отрицательная маржа подсвечена: это ответ на
    вопрос «нужны ли лимиты по тарифу».
- **Предметы** — самые популярные предметы по обращениям, устройствам и расходу.
- **Удержание** — возврат на 1/7/30 день и недельные когорты.
- **Бот и отзывы** — напоминания о продлении, опрос ушедших («почему»),
  обращения и идеи из телеграм-бота, привязки Telegram.
- **Ошибки** — последние клиентские ошибки (без данных пользователя).
- **Модели ИИ** — живые цепочки Auto/Think, дешёвая и PDF-модель, общий
  минутный лимит, frontier-лимит, дешёвый лимит, глобальный предохранитель,
  аварийный режим и откат последних 10 сохранений. Базовая схема — 5 стартов
  в минуту, 15 frontier-запросов и ещё 70 дешёвых (до 85 в день на лицензию).
  Сохранение действует на следующий новый запрос всех пользователей;
  обновление расширения не требуется.

Период везде переключается: **день / неделя / месяц / всё** (московское время).

## Каким числам можно верить

Панель специально разделяет два вида данных, и это видно в баннере на «Обзоре»:

- **Полные, по всем:** выручка, возвраты, покупки, рефералы, бот и отзывы. Их
  пишет сервер на каждое событие, независимо от настроек пользователя.
- **Выборка:** устройства, браузеры, DAU/WAU/MAU, решения/тесты/ГДЗ, предметы,
  удержание, ошибки, серверные вызовы 302.AI. Телеметрия в расширении
  **выключена по умолчанию** (`telemetryEnabled = false`), и VPS-прокси тоже
  ничего не шлёт без явного согласия. Цифры настоящие, но это нижняя граница —
  установок и решений всегда больше, чем видит панель.

Возвраты считаются по дате возврата денег, поэтому возврат старой покупки
попадает в текущий период — это обычная бухгалтерская логика, а не ошибка.
«Отозвано ключей» — не то же самое, что возврат: ключ можно отозвать за
злоупотребление, не возвращая деньги.

Красная полоса сверху («Нужно вмешаться») показывается только когда что-то
действительно застряло — например, деньги получены, а ключ не доставлен. Если
проверить очереди не удалось, она так и пишет: это **не** значит, что всё чисто.

Ключи лицензий панель показывает последними 4 символами. Ключ — это предъявительский
токен, который активирует продукт, а ключ статистики доступен из браузера.

## Как это работает

Данные приходят из воркера лицензий (`smesh-licenses` на Cloudflare) через
эндпоинты `GET /admin/stats/*`, защищённые заголовком `x-stats-token`
(секрет `STATS_SECRET` на воркере). Это **отдельный ключ только для чтения** —
не `ADMIN_SECRET`. Воркер отклоняет любой запрос с заголовком `Origin` на
маршрутах выдачи/отзыва лицензий, а preflight для статистики разрешает ровно
`Content-Type, X-Stats-Token`. Поэтому браузер с админ-ключом не получал 401,
а падал с «Failed to fetch»: запрос блокировался до отправки.

Расширение шлёт **обезличенную** телеметрию на `POST /t` — только типы событий,
предметы, счётчики токенов и стоимость, без текста заданий и ответов.

При первом входе введите ключ статистики — он хранится в `localStorage` этого
браузера.

Раздел «Модели ИИ» подключается к VPS `https://ai.smeshapi.site` отдельным
`MODEL_ADMIN_KEY`. Это не `ADMIN_SECRET`, не `STATS_SECRET` и не ключ 302.AI.
Ключ управления хранится только в `sessionStorage` вкладки и удаляется при
выходе из панели. VPS принимает этот маршрут только с точного origin
`https://ayeepat.github.io`, проверяет ревизию перед записью и сохраняет
конфигурацию атомарно в `/var/lib/smesh-proxy/model-config.json`.

Первичная настройка VPS:

```bash
openssl rand -hex 32
# вставить результат в /etc/smesh-proxy.env как MODEL_ADMIN_KEY=...
# MODEL_DASHBOARD_ORIGIN=https://ayeepat.github.io
sudo systemctl restart smesh-proxy
```

Можно указывать любую модель 302.AI, которая работает через OpenAI-совместимый
`/v1/chat/completions`. Модели с отдельным vendor-specific API одним model id
переключить нельзя. Для изображений и PDF оставлены отдельные цепочки, чтобы
текстовая модель не получила файл, который она не умеет читать.

Auto по-прежнему называется `deepseek` только в протоколе старых версий
расширения. Через него идут и домашка, и решение тестов.

Политику качества VPS применяет к **фактической модели**, а не к route — у
каждой модели свой рычаг мышления:

- пресет **Qwen 3.7 Plus** (по умолчанию) ставит `qwen3.7-plus` на текст и
  изображения. Qwen думает всегда, уровней усилия у него нет, поэтому VPS не
  шлёт ему `reasoning_effort`, а на запросах с картинкой снимает ещё и
  `json_object` — с изображением JSON-режим у Qwen ненадёжен;
- пресет **GLM-5.3-Flash** ставит `glm-5.3-flash`, и VPS принудительно включает
  ему thinking с `reasoning_effort=max`;
- пресет **DeepSeek** возвращает `deepseek-v4-flash` только для текста и
  оставляет изображения на мультимодальной модели, потому что DeepSeek V4 не
  поддерживает vision.

Дешёвая цепочка намеренно остаётся на `glm-5.3-flash`: она включается после
frontier-лимита, а GLM примерно вчетверо дешевле Qwen 3.7 Plus за токен.

В цепочку изображений можно ставить только модели с vision. Текстовая модель
(например `qwen-plus`) отвечает на картинку не ошибкой, а HTTP 200 с уверенной
выдумкой — это хуже, чем отсутствие ответа.

Пересборка таблицы покупок из KV — операция с админ-правами, из браузера она
недоступна by design. С машины, где лежит `ADMIN_SECRET`:

```bash
curl -X POST https://smeshapi.site/admin/backfill-licenses -H "x-admin-token: $ADMIN_SECRET"
```

## Локальный запуск

```bash
python3 -m http.server 4599
# открыть http://localhost:4599
```

Адрес бэкенда меняется в `API_BASE` в начале `app.js`; курс $→₽ живой —
официальный курс ЦБ РФ, который отдаёт воркер (`/admin/stats/rate`), кэш 12ч.
Адрес VPS для управления моделями задаётся в `MODEL_API_BASE` рядом с ним.
